# Changelog

All notable changes are documented here. The project follows semantic versioning after the public API reaches `1.0.0`.

## 0.1.0 - 2026-08-08

Initial public release.

### Added

- an enterprise authorization and multi-tenancy layer that enforces per-principal access control over every evidence path (lexical and vector retrieval including HyPE and RAPTOR, graph facts, RLM recursion, citations, the answer cache, session memory, learned preferences, and every program and HTTP surface), where a deployment brings its own identity through a `PrincipalResolver` and its own policy through an `AccessPolicy` that can route the decision to an external engine such as OPA or Cedar, evidence is tagged at ingestion with an `acl` block (classification plus allow and deny lists and tenant) whose permission travels source to document to chunk to graph fact to retrieval to citation, and the whole layer is byte-identical when unconfigured and fail closed when active, denying an untagged or malformed unit, refusing a cross-tenant request through a framework pre-policy guard even under a custom policy, and never trusting a client-supplied identity or letting a model decide a permission;
- trusted server-side identity resolution: the HTTP boundary resolves a principal only from an authenticated server-side context through a configured resolver and never from the request body, with human, service, and system principal kinds representable and entitlements separated from arbitrary claims;
- an enterprise audit event contract that is redacted by construction (ids, counts, policy, and timestamps only, never a raw query, evidence text, or secret) emitted once per served query and RLM run, a durable at-least-once audit outbox with a bounded retry backoff and a per-sink delivery ledger, and an opt-in fail-closed audit policy under which a served or state-changing path refuses rather than proceeds when the audit sink is unavailable, all byte-identical when no sink is installed;
- durable tool-call approvals for a governed ReAct trajectory: a requires-approval capability gates a tool behind a durable, single-use approval record with an HTTP approval surface and a four-eyes grant, consume, and cancel flow, each step emitting a redacted audit event, the approval fingerprint bound to the content-addressed program artifact id and to a granted skill's class identity so any change to the program, its policy, its capabilities, or its skills invalidates every prior approval, and the whole path byte-identical when no capability is declared;
- data-classification model routing: a deterministic router that derives the evidence classification from the ACL tags of the retrieved hits and refuses generation over evidence above a configured classification ceiling before any evidence reaches the model, the refusal reason kept generic so it is not a probing side channel, the router identity folded into the answer-cache identity, a model never able to override the decision, and the no-router default byte-identical;
- output governance and generation-evidence egress redaction that constrain what a generated answer may carry off the evidence boundary, applied on the answer path without altering a grounded citation and byte-identical when unconfigured;
- execution-time secret handling for skills and connectors so a secret is supplied at execution and never persisted into a program artifact, a cache key, or an audit event, byte-identical when unused;
- data-subject right-to-erasure, legal holds, and kill switches as first-class, admin-scoped, audited governance operations, byte-identical when unused;
- an opt-in per-corpus derivation manifest that records the materialization recipe (chunking, embedding, and graph settings and the concrete adapter identities), the row counts, and an order-independent content checksum, refreshed on every ingest, delete, and erase and verifiable against committed state, byte-identical when unused;
- an opt-in `legal_hold_on_conflict` defer policy: an erasure that meets an active legal hold is recorded as a durable pending request and executed when the last hold covering the document is lifted, re-checking the hold under the corpus destroy lock so a document still held is never erased, with a `deferred_erasure.sweep` worker job as the at-least-once backstop that re-drives any request stranded by a lift-time failure, and the default refuse policy byte-identical;
- a legal-hold permission-history ledger: when a document under an active legal hold has its access-control state changed by a re-tag, the change is recorded append-only in the same transaction as the re-tag with the old and new permission fingerprint, the old and new canonical ACL, the covering hold ids, and the attributed actor, so who could see the held evidence stays reconstructable and the prior ACL is never silently overwritten, and the permission fingerprint is a canonical-JSON digest so an ACL member name containing a comma can never collide two distinct ACLs, byte-identical when no hold covers the document;
- a pluggable chunking layer: the document chunker is a `ChunkingStrategy` port with the three built-in strategies (flat, parent_child, sentence_window) as byte-identical defaults, a custom or domain chunker injected through `with_chunking_strategy` or discovered through the allowlisted `refaat.chunkers` plugin group, and contextual embedding, HyPE, and RAPTOR composing on any conforming strategy without change;
- a machine-readable port catalog describing every typed Protocol port (its required members, injection tier and seam, default, and the invariant an adapter must uphold), a `ports_catalog` gate that fails closed when the catalog drifts from the live ports or a declared seam does not correspond to its port, the generated `refaat plugin ports` and `refaat plugin describe` discovery commands, and the Ports catalog reference page kept in lockstep with the code;
- a plugin scaffolder and conformance kit: `refaat plugin new <Port> <name>` writes an installable adapter project from the catalog (a member stub taken from the live port, the correct entry-point block or builder snippet, a conformance test, and a README), and `refaat plugin verify <module:Class> --port <Port>` checks an adapter implements every member the port declares and exits non-zero when it does not;
- governed outbound HTTP for a plugin skill: a skill opts in with a `wants_outbound` marker and receives a governed `OutboundClient` only when its capability declares the EXTERNAL side effect, so a read-only or capability-less skill cannot send bytes; every request flows through the per-capability allow-list, the deployment egress allowlist, an SSRF pin that always refuses a private address, a disabled-redirect send, and a response byte cap, the admission is audited before any byte leaves the socket with a redacted event that carries only the host and a reason code, an unserved shadow or canary run refuses every request, and the direct skill path refuses a `wants_outbound` skill outright; byte-identical for a skill with no marker;
- a `refaat plugin pin <group>:<name>` command that computes an installed plugin's content-hash pin without importing its code and prints the exact `REFAAT_PLUGIN_PINS` fragment, refusing to print a pin the runtime would then reject;
- pluggable cache backends: the version-aware answer cache and the model-call cache each become a typed port selected by `REFAAT_ANSWER_CACHE_BACKEND` and `REFAAT_MODEL_CALL_CACHE_BACKEND` (both default `sql`, byte-identical), with a reference Redis backend behind an optional extra where a read or write degrades to a miss on a transient outage so a query still serves, a right-to-erasure enumerates the real keys with `SCAN` (re-scanning until a pass is empty) and removes them with `UNLINK` fail-closed rather than reporting a false erasure, erasure sweeps the store and the currently configured backend (a backend migration erases before the old backend is decommissioned), key segments are fixed-width digests so an id can never inject a glob metacharacter, and either cache is injectable in process through `with_cache_store` and `with_model_call_cache`;
- an opt-in term-indexed graph read (`REFAAT_GRAPH_TERM_INDEX_ENABLED`, default off and byte-identical) that replaces the full-corpus graph load on the query and RLM paths with an `entity_terms`-indexed fetch of only the query-relevant subgraph (matched entities by substring or token, every relation touching them, and the one-hop endpoint frontier), feeding the unchanged `graph_context` so it never under-returns and, for a query within the twenty-fact prompt cap, produces identical boosts, answer, and citations to the full scan; a query beyond a configurable char cap or a corpus without the index falls back to the full scan, so the read is never an empty graph;

### Changed

- strict authorization is the recommended production default (`strict_authorization` defaults to `true`). When an access policy is installed and no principal is supplied, an in-process evidence call (query, retrieve, RLM, program run, skill run, document listing, feedback) now fails closed with an `AuthorizationError` instead of serving unfiltered. Set `strict_authorization=false` to restore the previous trusted-in-process behavior. The no-policy path is unchanged, worker evidence jobs already fail closed by re-resolving the enqueue-time principal, and the HTTP boundary already resolved identity server-side.
